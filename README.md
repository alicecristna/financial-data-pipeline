# Financial Data Pipeline

A small, offline-reproducible data pipeline for daily equity prices:

**CSV ingestion → SQLite storage → returns & risk metrics → factor backtesting**

Live fetching from yfinance (US equities) and baostock (A-shares) is optional.
The repository ships a **deterministic synthetic CSV snapshot** (fixed seed,
neutral asset names, generated by `scripts/generate_demo_data.py`) so that
tests and the demo run with no network access and no credentials.

## Architecture

| Module | Responsibility |
| --- | --- |
| `core/data_fetcher.py` | Optional yfinance/baostock clients. Imports fail gracefully; live download paths are not exercised by tests or the demo. |
| `core/database.py` | SQLite (WAL) storage. `insert_prices` is an idempotent `INSERT OR REPLACE` upsert on `(ticker, date)`; `upsert_price_rows` lets callers own the transaction. |
| `core/pipeline.py` | `DataPipeline.update_daily_prices`: download → tidy → per-ticker delete + insert + log in one rollback-safe SQLite transaction (direct `executemany`, no `pandas.to_sql`). |
| `core/processor.py` | Normalises several yfinance CSV layouts (with/without ticker row) into a date-indexed price matrix; preserves missing prices by default (`ffill` is explicit opt-in); builds day-ahead direction labels. |
| `core/risk_metrics.py` | Rolling/EWMA volatility, Sharpe, historical VaR and drawdowns, plus a small `RiskReport` summary. |
| `core/factor_backtest.py` | Momentum/volatility/MA factors, long(-short) signals, simple-return equal-weight accounting, performance stats and Rank IC. |
| `core/utils.py` | Logging, conservative dtype optimisation, price-data validation. |
| `demo.py` | Offline end-to-end demo on the synthetic CSVs. |
| `scripts/generate_demo_data.py` | Reproducibly regenerates the synthetic `data/` snapshot. |

## Quick start (offline)

```bash
python -m pip install -r requirements-dev.txt
python -m pytest          # deterministic unit tests, no network
python demo.py            # offline end-to-end demo, no network
```

Live data fetching is optional and requires the extra dependencies in
`requirements.txt` plus network access:

```python
from core.data_fetcher import DataFetcher
from core.pipeline import DataPipeline

pipeline = DataPipeline("financial_data.db")
pipeline.update_daily_prices(["AAPL"], years_back=2)  # any Yahoo ticker
pipeline.close()
```

## Tested behavior

All claims below are covered by deterministic tests in `tests/` that run
without network access:

- **CSV layouts** — `DataProcessor` reads yfinance exports with a ticker row,
  plain header-only CSVs, and the rate-style `Price`/`Ticker`/`Date` preamble.
  The first data row is never silently dropped.
- **Idempotent, atomic writes** — calling `DatabaseManager.insert_prices` twice
  with the same rows does not raise and does not duplicate; the same
  `(ticker, date)` with new values is replaced. `DataPipeline.update_daily_prices`
  runs delete, insert and `update_log` inside a single SQLite transaction, and a
  forced failure in the log write rolls the update back (old prices remain, no
  partial rows). The `update_log` is an append-only audit trail by design.
- **Simple-return accounting** — position P&L and equal-weight portfolio returns
  use simple (not log) returns. A 50/50 basket where one asset gains 100% and
  the other loses 50% compounds to exactly +25% total return.
- **Execution and commission timing** — executed positions come from
  `signals.shift(1)` in one shared helper; the opening trade from zero position
  is charged; a final signal that would only execute after the sample is not
  charged; a missing signal is treated as flat (and the following signal as a
  re-entry).
- **Missing data** — `DataProcessor.process_prices` defaults to no filling
  (`fill_method=None`), so missing prices stay `NaN`. Passing such a panel to
  `FactorBacktest` raises a clear `ValueError` rather than forward-filling:
  only the first return row may be missing, later missing or non-finite returns
  are rejected, and the equal-weight mean uses `skipna=False`.
  `fill_method="ffill"` is an explicit caller opt-in that changes the data
  semantics (previous value carried forward); unsupported values raise
  `ValueError`. This describes the shipped default path, not every possible
  caller configuration.
- **Drawdowns** — global drawdowns include initial wealth (1.0 for
  `FactorBacktest` max drawdown, 100 for `RiskMetrics.current_drawdown`), so a
  first return of −20% produces a −20% drawdown rather than 0.
  `RiskMetrics.rolling_max_drawdown` is instead computed per trailing return
  window: each window starts at relative wealth 1.0 and uses only that window's
  returns, so `[-20%, 0]` followed by a flat window gives 0%, while two −10%
  days inside one window give −19%.
- **Risk metrics** — `rolling_volatility(annualize=False)` returns periodic
  values and `annualize=True` scales them by `sqrt(252)`; `historical_var` uses
  `quantile` and works both globally and with a rolling window;
  `rolling_sharpe(annualize=False)` returns the periodic ratio and
  `annualize=True` scales it by `sqrt(252)`; `rolling_beta` uses matching
  covariance/variance degrees of freedom (a doubled benchmark exposure gives
  beta 2); `ewma_sharpe` uses exponentially weighted variance rather than a
  root-mean-square; zero-volatility rolling, expanding and EWMA Sharpe values
  return `NaN`, never `±inf`.
- **Sharpe definition** — `FactorBacktest.calculate_performance` annualises the
  periodic mean-to-standard-deviation ratio by `sqrt(252)`; it does not divide
  compounded return by volatility. A deterministic regression fixture pins the
  formula; it is not a market result.
- **Factor IC** — Rank IC correlates the factor at date `t` with the `t → t+1`
  return only; the last date is excluded because it has no forward return.
  A double-shift regression test guards the alignment.
- **Signal semantics** — `generate_signals(..., short_threshold=None)`
  produces no short positions; an explicit threshold enables them.
- **Missing future labels** — `direction_label` returns `NaN` for the final row
  so it is dropped instead of being labelled "down".
- **Offline operation** — `demo.py` and the whole test suite run without
  yfinance/baostock and make no network calls.
- **pandas 2/3 compatibility** — dtype optimisation detects text columns
  whether they are object-backed (pandas 2) or `StringDtype` (pandas 3); CI
  runs the suite against both pandas lines.

## Limitations

- The `data/` files are synthetic random walks (fixed seed, neutral names),
  not market history. They have no economic meaning and must not be presented
  as market data or used for investment conclusions. See `data/README.md`.
- The demo output is a mechanical computation on that synthetic input. It is
  **not** a performance claim, was not benchmarked against any baseline, and
  carries no implication of predictive skill or profitability.
- The factor backtest ignores borrow costs, market impact, taxes and
  survivorship/delisting; it charges only a flat per-trade commission when
  `calculate_net_returns` is used. Results cover a single short window.
- SQLite is a single-writer store; the pipeline is not designed for concurrent
  writers.
